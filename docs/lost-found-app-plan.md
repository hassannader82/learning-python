# تطبيق المفقودات (مقترح شامل)

## الهدف
إنشاء تطبيق موبايل حديث يربط بين فاقدي المقتنيات ومن يجدها، مع تجربة آمنة وسهلة لجميع المستخدمين. هذا المستند يمثّل **النسخة الأولى المقترحة (V1)** التي نبدأ بها فعليًا.

## الوظائف الأساسية (MVP)
1. **تسجيل الدخول والحسابات**
   - تسجيل باستخدام رقم الهاتف/البريد.
   - كلمة مرور مع استرجاع كلمة المرور.
   - ملف شخصي بسيط (الاسم، المدينة، وسيلة تواصل).

2. **إضافة بلاغ مفقود**
   - عنوان البلاغ ووصف مختصر.
   - مكان الفقد (مدينة + حي + خريطة اختيارية).
   - وقت الفقد (تاريخ/وقت تقريبي).
   - نوع المفقود (قائمة أنواع).
   - صور للمفقود (حتى 3 صور).

3. **أنواع المفقودات المقترحة**
   - ذهب/مجوهرات
   - فضة/إكسسوارات
   - حيوان أليف
   - محفظة/هوية
   - هاتف/إلكترونيات
   - مفاتيح
   - حقيبة/حقيبة يد
   - وثائق رسمية
   - سيارة/دراجة
   - أخرى (مع وصف)

4. **التعليقات على البلاغات**
   - تعليقات عامة على البلاغ (معلومات/تنبيهات).
   - زر “وجدته” لتحويل التفاعل إلى محادثة مباشرة.

5. **المراسلة المباشرة (Chat)**
   - تبدأ عند ضغط “وجدته”.
   - تبادل رسائل وصور لتأكيد المقتنى.

6. **النسخة الأولى المقترحة (V1)**
   - تسجيل دخول + ملف شخصي أساسي.
   - إضافة بلاغ مفقود مع صورة واحدة (قابلة للزيادة لاحقًا).
   - قائمة المفقودات مع بحث بسيط حسب المدينة/النوع.
   - تعليقات عامة + زر “وجدته”.
   - محادثة مباشرة نصية فقط كبداية.
   - حالة البلاغ: (مفقود / تم التسليم).

## التوسعات المقترحة (بعد الإطلاق الأول)
- **فلترة وبحث متقدم** (المنطقة، النوع، التاريخ، الحالة).
- **حالات البلاغ** (مفقود، قيد التحقق، تم التسليم).
- **نظام بلاغات/إساءة الاستخدام** للمحتوى غير المناسب.
- **تنبيهات ذكية** عند إضافة بلاغ قريب من موقع المستخدم.
- **نقاط موثوقية** للمستخدمين الذين ساعدوا الآخرين.

## تجربة المستخدم (UX/UI)
- تصميم عصري بسيط (Minimal)
- ألوان هادئة مع لون أساسي واضح للنداء (CTA)
- بطاقات (Cards) لبلاغات المفقودات مع صورة + عنوان + المنطقة
- شريط بحث علوي مع فلترة سريعة
- زر إضافة بلاغ (FAB) واضح

## الاقتراحات البصرية
- **ألوان**: أزرق داكن + تركواز + أبيض (موثوقية + وضوح).
- **خطوط**: خطوط عربية حديثة مثل Cairo أو Tajawal.
- **أيقونات**: بسيطة وواضحة (Material Icons).

## فكرة شعار التطبيق (Logo)
- دمج بين **موقع + يد** (Pin + Hand) للدلالة على المساعدة.
- شكل دائري بسيط مع نقطة مكان داخلها رمز القلب.
- اسم مقترح: **"لقيته"** أو **"مفقودات"** أو **"عين المكان"**.

## تدفق الاستخدام الأساسي
1. المستخدم يسجّل دخول.
2. يضيف بلاغ مفقود.
3. يظهر البلاغ في الصفحة الرئيسية.
4. مستخدم آخر يعلّق أو يضغط “وجدته”.
5. تبدأ محادثة مباشرة لتأكيد الاستلام.
6. تحديث حالة البلاغ إلى “تم الاستلام”.

## التقنية المقترحة (أندرويد كبداية)
- **الواجهة**: Kotlin + Jetpack Compose (تصميم حديث وسريع)
- **الخلفية**: Firebase (Auth, Firestore, Storage)
- **الخرائط**: Google Maps SDK
- **الإشعارات**: Firebase Cloud Messaging

## قاعدة البيانات (نماذج مختصرة)
- **Users**: id, name, city, phone/email, avatar
- **LostItems**: id, userId, title, description, category, location, time, photos, status
- **Comments**: id, itemId, userId, text, createdAt
- **Chats**: id, itemId, members, lastMessage
- **Messages**: id, chatId, senderId, content, createdAt

## الأمان والخصوصية
- إخفاء معلومات التواصل حتى فتح المحادثة.
- سياسة واضحة لإزالة المحتوى المخالف.
- صلاحيات رفع الصور بحجم محدود.

---

## خطة عمل مختصرة للانطلاق (V1)
1. رسم واجهات أولية (Wireframes) للصفحات الأساسية.
2. بناء نموذج قاعدة البيانات في Firebase.
3. تنفيذ تسجيل الدخول والملف الشخصي.
4. بناء تدفق إضافة بلاغ + شاشة القائمة.
5. إضافة التعليقات وميزة “وجدته” مع محادثة نصية.
6. اختبار تجريبي مع 5–10 مستخدمين وتعديل بناءً على الملاحظات.

> هذا المقترح يصلح كنقطة انطلاق لتخطيط التصميم وتطوير النسخة الأولى للأندرويد.
